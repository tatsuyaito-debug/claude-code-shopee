# 発送代行（ShopeeKing）を使う

梱包と発送を代行業者に任せる運用です。`config/fulfillment.yaml` の `active` を
切り替えるだけで、**利益計算・作業フロー・リードタイムがまとめて切り替わります。**

---

## ShopeeKing とは

株式会社ten. が運営する、Shopee輸出セラー向けのサービスです。
コミュニティ、出品・受注管理ツール、**発送代行**がセットになったサブスクリプションで、
発送代行では商品を同社の倉庫に納品すると、**梱包・ラベル貼付・SLS倉庫への発送**を代行してもらえます。

費用は一般に「入庫料 ＋ 梱包料 ＋ 資材費（プチプチ・段ボール）＋ SLS倉庫までの国内送料」という構成です。

> ⚠️ **料金の実数はこのリポジトリには入っていません。**
> プランや時期で変わるため、ShopeeKing の管理画面・契約書・見積りを見て、
> 次の「設定手順」で自分の数字を入れてください。入れるまで比較ツールは警告を出して止まります。

---

## 設定手順

### ステップ1: 料金を6つ集める

ShopeeKing から、次の数字を確認してください。**これが揃わないと損得の判断ができません。**

| 集める数字 | `fulfillment.yaml` の項目 | 補足 |
|---|---|---|
| 入庫料（1個あたり） | `inbound_jpy` | 倉庫で受け取ってもらう費用 |
| 梱包代行料（1個あたり） | `pick_pack_jpy` | ピッキング・梱包・ラベル貼付 |
| 資材費（1個あたり） | `material_jpy` | プチプチ・段ボールなど |
| 倉庫→SLS倉庫の国内送料（1個あたり） | `domestic_to_sls_jpy` | |
| 月額料金 | `monthly_fixed_jpy` | サブスクの月額 |
| 自分が倉庫へ送るときの送料（1回） | `inbound_shipping_jpy_per_lot` | 宅配便の実費 |

### ステップ2: `config/fulfillment.yaml` に書く

```yaml
active: shopeeking          # ← ここを切り替えると運用が変わる

providers:
  shopeeking:
    updated_at: 2026-09-21  # 料金を確認した日
    per_unit:
      inbound_jpy: 30
      pick_pack_jpy: 120
      material_jpy: 50
      domestic_to_sls_jpy: 180
    inbound_shipping_jpy_per_lot: 1200   # 1回の納品にかかる宅配便代
    lot_size: 20                         # 1回に何個まとめて送るか
    monthly_fixed_jpy: 9800              # 月額
    expected_monthly_units: 50           # 月に何個出荷する想定か
    handling_days: 1
```

### ステップ3: 損得を確認する

```bash
python3 scripts/compare_fulfillment.py --sku BIB-001 --monthly-units 60
```

こんな結果が出ます。

```
  想定出荷数: 月 60 個
  1個あたり発送費: 自社 360円  →  ShopeeKing 発送代行 603円  （差 +243円）
  月あたりの差額: +14,600円
  空く時間: 月 7.0 時間
  → その時間を **時給 2,086円 で買う** ことになります
     あなたの時間の値段 1,500円/時 より高い → ⚠️ 出荷数が増えるまで待つ
```

**これが判断の核心です。** 代行は「現金を払って時間を買う」取引なので、
時給が自分の時間の値段より安くなったら任せる、が正しい判断になります。

同じ設定でも出荷数が増えると結果が変わります。

```
  想定出荷数: 月 200 個
  → その時間を **時給 1,106円 で買う** ことになります
     あなたの時間の値段 1,500円/時 より安い → ✅ 任せる価値あり
```

`config/business.yaml` の `operations.hourly_value_jpy`（既定1,500円）が
判断の基準です。自分の感覚に合わせて変えてください。

### ステップ4: 全商品の価格を見直す

**切り替えると1個あたりの発送費が変わるので、既存の売価が下限を割ることがあります。**

```bash
python3 scripts/calc_price.py --sku BIB-001 --fulfillment shopeeking
```

AI社員にまとめて確認させることもできます。

> 発送をShopeeKingに切り替えたら、いまの出品価格で下限を割る商品はある？

## 切り替えたあと、何が変わるか

| | 自社発送 | ShopeeKing 発送代行 |
|---|---|---|
| 毎日の梱包作業 | あり（1件8分程度） | **なし** |
| あなたの主な仕事 | 梱包・発送 | **倉庫への納品計画** |
| 在庫の場所 | 手元だけ | 手元 ＋ **代行倉庫**の2箇所 |
| 補充のリードタイム | 仕入れ → 手元 | 仕入れ → 手元 → **倉庫へ納品** |
| 出荷までの日数 | 2日 | 1日（設定値） |
| 1個あたりの現金支出 | 少ない | 多い |

### 一番気をつけること：倉庫在庫を切らさない

**手元に在庫があっても、倉庫に無ければ出荷できません。**
代行モードでは、これが唯一にして最大の事故要因です。

AI社員（受注・発送担当）が納品計画を出します。

> 倉庫に何個納品すればいい？

```
## 代行倉庫への納品計画（次回 3/15 発送・合計 24個）

| SKU | 倉庫在庫 | 週販 | 残り日数 | 納品数 | 理由 |
|---|---|---|---|---|---|
| BIB-001 | 4 | 5個/週 | 5日 | 15 | 納品リードタイム(7日)に間に合わない。最優先 |
| PCH-003 | 2 | 2個/週 | 7日 | 9 | ギリギリ。今回の便に混ぜる |
```

### 納品はまとめる

納品送料は1回いくらなので、**小口で何度も送ると1個あたりの負担が跳ね上がります。**

- 1,200円の送料を **20個** で割る → 1個 **60円**
- 同じ1,200円を **5個** で割る → 1個 **240円**

`lot_size` に届かないときは、近いうちに切れそうなSKUを前倒しで足して1便にまとめてください。

### 納品前に自分でやること

代行倉庫は**検品まではしてくれない前提**で考えてください。

- □ 商品の検品（汚れ・ほつれ・不良）— ベビー用品のクレームは重い
- □ 値札・日本語の価格シールを剥がす
- □ SKUごとに分けて、外箱にSKUと数量を明記する

---

## いつ切り替えるべきか

迷ったら、この順で考えてください。

1. **月20個以下**: 自社発送のまま。月額費の1個あたり負担が重すぎます
2. **月20〜60個**: `compare_fulfillment.py` で時給を確認。時給が高すぎるなら見送り
3. **月60個以上、かつ梱包が出品作業を圧迫している**: 切り替えを検討
4. **切り替えたら、空いた時間を必ず新規出品に使う**

> 💡 **時間が空いても何もしないなら、代行はただの赤字です。**
> 「月7時間空いて、その7時間で出品を10品増やせる」なら元が取れます。
> そこまで含めて判断してください。

---

## 元に戻したいとき

`config/fulfillment.yaml` の `active` を `self` に戻すだけです。
価格の見直し（ステップ4）だけ忘れずに行ってください。
