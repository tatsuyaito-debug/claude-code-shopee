# 運用フロー図

オペレーションの全体像です。GitHub上ではそのまま図として表示されます。

---

## 1. 全体像：4つの工程がぐるぐる回る

このお店は「商品を増やす → Shopeeに出す → 注文を回す → 数字で直す」の4工程が
1周するだけの仕組みです。その下に、すべての判断の根拠になる**設定レイヤー**があります。

```mermaid
flowchart LR
    A["① 商品を増やす<br/>週 60分<br/>リサーチ→値付け→出品"]
    B["② Shopeeに出す<br/>CSVを一括アップロード"]
    C["③ 注文を回す<br/>日 15-30分<br/>発送・CS返信"]
    D["④ 数字で直す<br/>週 30分<br/>週次レポート"]

    A -->|"出品CSV"| B
    B -->|"注文が入る"| C
    C -->|"注文CSVを書き出す"| D
    D -->|"売れた商品の横展開<br/>赤字SKUの値上げ"| A

    CFG["設定レイヤー config/*.yaml<br/>business / markets / fulfillment / compliance"]
    CFG -.->|"判断の根拠"| A
    CFG -.->|"判断の根拠"| C
    CFG -.->|"判断の根拠"| D
```

> 💡 **④から①に戻る矢印がこの仕組みの要です。** 売れた商品の色違いを足すのが、
> 一番確実な伸ばし方。新しい商品をゼロから探すより先にここを回してください。

## 2. 商品を増やす（①の詳細）：3箇所で止まる

仕入れ候補が出品に至るまでに、**3回ふるいにかけます。** どれかで止まったら引き返します。

```mermaid
flowchart TD
    START["仕入れ候補<br/>西松屋・Amazon・卸サイト"]

    R{"リサーチAI<br/>規制チェック"}
    P{"値付けAI<br/>利益チェック"}
    L{"出品AI<br/>表現チェック"}

    OUT1["⛔ 仕入れない<br/>粉ミルク・チャイルドシート<br/>電池入りおもちゃ など"]
    OUT2["⚠️ 要確認<br/>歯固め・ベビー食器<br/>スキンケア など"]
    OUT3["⛔ 仕入れない<br/>損益分岐点を割る<br/>重い・大きい・低単価"]
    OUT4["🔁 書き直し<br/>効能をうたう表現<br/>タイトル120字超<br/>画像3枚未満"]

    CSV["出品CSVを書き出す<br/>build_listing_csv.py"]
    IMG["Seller Centre で画像を手動アップロード<br/>※画像ファイルはCSVに載らない"]
    DONE["Shopeeに出品"]

    START --> R
    R -->|"禁止カテゴリ"| OUT1
    R -->|"要確認カテゴリ"| OUT2
    R -->|"問題なし"| P
    P -->|"利益が足りない"| OUT3
    P -->|"利益が残る<br/>calc_price.py"| L
    L -->|"NG表現あり"| OUT4
    L -->|"検証を通過<br/>--check-only"| CSV
    CSV --> IMG
    IMG --> DONE
    OUT4 -.->|"直して再検証"| L
```

**止まる場所と、止める理由**

| 止まる場所 | 何を見ているか | 止める理由 |
|---|---|---|
| リサーチAI | `config/compliance.yaml` の禁止・要確認カテゴリ | アカウント停止・法令違反を防ぐ |
| 値付けAI | 送料・手数料・為替込みの損益分岐点 | 「売れてるのに儲からない」を防ぐ |
| 出品AI | 禁止表現・文字数・画像枚数 | 薬機法的なNG表現とShopeeの弾きを防ぐ |
| 比較ツール | 発送代行の料金が未入力か | 「代行はタダ」という誤った結論を防ぐ |

## 3. 注文を回す（③の詳細）：発送モードで分岐する

`config/fulfillment.yaml` の `active` によって、**毎日の仕事がまるごと変わります。**

```mermaid
flowchart TD
    ORDER["Shopeeに注文が入る"]
    MODE{"config/fulfillment.yaml<br/>active は？"}

    subgraph SELF["active: self（自社発送）"]
        S1["注文CSVをダウンロード"]
        S2["検品・値札を剥がす<br/>OPP袋で個包装"]
        S3["梱包<br/>※薄くするほど送料が下がる"]
        S4["SLSラベルを貼って発送"]
        S1 --> S2 --> S3 --> S4
    end

    subgraph AGENCY["active: shopeeking（発送代行）"]
        A1["代行倉庫が梱包・発送<br/>自分は手を動かさない"]
        A2["やることは倉庫在庫の確認だけ"]
        A1 --> A2
    end

    subgraph SUPPLY["代行モードで増える仕事（週〜隔週）"]
        W1["販売ペースから倉庫在庫の残り日数を計算"]
        W2["lot_size にまとめて納品<br/>※小口だと納品送料で利益が溶ける"]
        W3["検品・値札剥がしは納品前に自分でやる"]
        W1 --> W2 --> W3
    end

    CS["CS返信<br/>12時間以内が目標"]
    DONE2["発送完了"]

    ORDER --> MODE
    MODE -->|"self"| S1
    MODE -->|"shopeeking"| A1
    S4 --> DONE2
    A2 --> DONE2
    ORDER --> CS
    A2 -.->|"在庫が尽きそう"| W1
    W3 -.->|"倉庫に在庫を補充"| A1
```

> ⚠️ **代行モードの唯一にして最大の事故は「倉庫の在庫切れ」です。**
> 手元に在庫があっても、倉庫に無ければ出荷できません。

**どちらを選ぶかは計算で決める**

```bash
python3 scripts/compare_fulfillment.py --sku BIB-001 --monthly-units 60
```

代行は「現金を払って時間を買う」取引なので、**空いた時間を時給いくらで買うことになるか**で判断します。

## 4. データの流れ：どのファイルがどこから来て、どこへ行くか

```mermaid
flowchart LR
    SC["Shopee Seller Centre"]

    subgraph CONFIG["config/ — 判断の根拠（手で書く）"]
        C1["business.yaml<br/>目標・利益方針"]
        C2["markets.yaml<br/>為替・手数料・SLS送料"]
        C3["fulfillment.yaml<br/>発送主体と料金"]
        C4["compliance.yaml<br/>禁止カテゴリ・禁止表現"]
    end

    subgraph DATA["data/ — 実績データ"]
        D1["products/products.csv<br/>原価・重量・在庫"]
        D2["products/drafts/*.yaml<br/>出品案"]
        D3["orders/*.csv<br/>注文実績"]
        D4["reports/*.md<br/>週次レポート"]
    end

    subgraph SCRIPTS["scripts/ — 計算する道具"]
        P1["calc_price.py"]
        P2["compare_fulfillment.py"]
        P3["build_listing_csv.py"]
        P4["weekly_report.py"]
    end

    C1 --> P1
    C2 --> P1
    C3 --> P1
    C3 --> P2
    C4 --> P3
    D1 --> P1
    D1 --> P4
    D2 --> P3
    D3 --> P4

    P1 -->|"推奨売価"| D2
    P3 -->|"出品CSV"| SC
    SC -->|"注文CSVを書き出す"| D3
    P4 --> D4
    D4 -->|"赤字SKU・在庫アラート"| C1
```

**手で書くのは `config/` と `data/products/products.csv` だけです。**
あとはAI社員がスクリプトを動かして作ります。

ただし **画像だけは例外**です。画像ファイルはCSVに載らないため、
CSVで商品を作ったあとに Seller Centre の商品編集画面で手動アップロードします。
写真は `data/products/images/<SKU>/` に置き、`build_listing_csv.py` が
サイズと並び順をチェックして手順書を書き出します。

## 5. 運用のリズム

| 頻度 | やること | 時間 | AI社員への一言 |
|---|---|---|---|
| **毎日** | 今日やることを3つに絞る | 5分 | 「今日なにをやればいい？」 |
| 毎日 | 発送（自社発送モードのみ） | 15分 | 「今日の発送分は？」 |
| 毎日 | チャット返信 | 10分 | 「このお客さんにどう返信する？」 |
| 毎日 | 新規出品（時間があれば） | 20分 | 「この商品を出品したい」 |
| **毎週** | ふりかえりと来週の打ち手 | 30分 | 「今週のふりかえりをして」 |
| 毎週〜隔週 | 倉庫への納品（代行モードのみ） | 30分 | 「倉庫に何個納品する？」 |
| **毎月** | 為替レートの更新 | 5分 | — （`config/markets.yaml` を直接編集） |
| 毎月 | 代行の料金改定・発送方法の再検討 | 10分 | 「代行に切り替えたほうが得？」 |

## 6. AI社員への振り分け

迷ったら店長AIに聞けば、適切な担当に振られます。

```mermaid
flowchart TD
    Q["「今日なにをやればいい？」"]
    M["🧑‍💼 店長AI<br/>shopee-manager"]

    R2["🔍 リサーチ<br/>何を仕入れるか"]
    P5["💰 値付け<br/>いくらで売るか"]
    L2["✍️ 出品<br/>タイトル・説明文・CSV"]
    C5["💬 顧客対応<br/>チャット・レビュー"]
    O2["📦 受注・発送<br/>発送・在庫・納品"]
    A5["📊 数字<br/>集計・レポート"]

    Q --> M
    M -->|"出品を増やすとき"| R2
    R2 --> P5
    P5 --> L2
    M -->|"注文・問い合わせがあるとき"| O2
    M -->|"返信が必要なとき"| C5
    M -->|"週次のふりかえり"| A5
    A5 -.->|"赤字SKUを見つけたら"| P5
    A5 -.->|"売れ筋を見つけたら"| R2
```
